## Required release gates

At local HEAD `f06148f7f373491bcb0d9a52f0438cca422ae75a`, `NPM_CONFIG_CACHE=/workspace/.npm-cache npm run release:check` passed on Node 24.22.3 with PostgreSQL 16 and Node 26.13.1 with PostgreSQL 17: each run passed 41 root test files / 164 tests, generated-project checks (9 files / 28 tests), CycloneDX SBOM validation (23 components), packed artifact smoke and reproducible dist; root and generated-project production dependency audits reported zero vulnerabilities. The generated production Docker image passed container health plus PostgreSQL readiness. The opt-in audit advisory mode returned verified clean LS023 evidence against the npm registry. Windows portability and CodeQL must pass on the final pushed head. Any runner quota or external service failure is recorded as unverified, not passed.

A clean-checkout CI run exposed that the generated API runtime files were present only under the package build output and ignored beneath the template source. The compiled template runtime is now checked in under `src/templates/api/dist`, so rebuilding `dist/` reproduces the package from a fresh clone. The same follow-up hardens template copying against symlinks. A later review found generated React query keys could collide across clients; they now include API base URL, operation method/path and caller-provided cache identity.

The #31 follow-up fixed silent audit truncation above Git's default 1 MiB output buffer. Path enumeration now has a 16 MiB and 10-second bound and emits LS022 when it cannot complete. LS005 is heuristic because it checks tracked filenames only. The audit now offers opt-in `--advisories` registry evidence for production dependencies and emits LS024 if that evidence cannot be obtained. See `docs/benchmarks/issue-31-security.md` for the measured traversal and its content-scanning limitation.

The first pushed ten-issue head exposed a transient race when concurrent writers observed a lock being released and reacquired between descriptor validation steps. The lock acquisition path now retries this specific identity-change condition; the separate-process 8/32 writer test and remote release matrix are rerunning on the updated head.

CodeRabbit skipped review because its configured limit is 100 changed files; its responses reported 219 and 224 files and no findings or approval. The consolidated PR is ready for review. The previous pushed head passed GitHub CI; commits `8e08293e18a275c9f9e478d36299e4de7efab9e8` and `f06148f7f373491bcb0d9a52f0438cca422ae75a` contain the independently reviewed follow-up fixes and repeated measurements; this head still needs remote CI and external review. GitHub CI also exposed a 5-second timeout in the TypeScript/React SDK compile fixture; its timeout is now raised to 30 seconds to accommodate the measured compiler work on shared runners. The Docker smoke had inherited a fallback system CA path that required a blocked BuildKit filesystem entitlement; it now mounts a CA bundle only when `NODE_EXTRA_CA_CERTS` is explicitly configured, matching the generated `stages docker` behavior.

PR #40 must receive review and green CI on its final head before release. Each material finding must be resolved or explicitly documented with evidence. The publish workflow is manually dispatched against `main`, requires its `authorize_publication` input, and uses the protected `npm-publish` environment. A tag push or ordinary main push does not publish. The package version remains exactly 3.0.4.

## Compatibility and known release risks

The package supports Node 24.22.3–24.x and 26.13.1–26.x. Node 20 is no longer supported, a semver breaking change under a patch version. Existing generated v3 projects retain their schema version; the registered project migration is v2.0.0 to v3.0.0. The CLI package release version does not imply a project schema migration.

Redis, queue and cron are local integrations. OAuth, storage, observability, WebSocket, email and webhook entries remain helper-only. Prisma remains on the generated project's Prisma 6 line; Prisma 7 migration is deferred. The qualification benchmark is diagnostic and does not establish a general latency or throughput guarantee.
