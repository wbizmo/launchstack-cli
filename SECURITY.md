# Security Policy

## Supported releases

Security reports are evaluated against the current supported LaunchStack CLI release and any additional explicitly supported release lines. The repository's release documentation and published npm versions identify current versions; no unverified long-term support commitments are implied.

## Reporting a vulnerability

Please **do not post exploit details or secrets in a public GitHub issue**. Use the repository's GitHub **Security → Report a vulnerability** private reporting feature when it is enabled. If that feature is unavailable, email **williams@zivoralabs.xyz** with “LaunchStack CLI security report” in the subject, requesting a confidential channel and including the affected version and impact. The maintainers must confirm that at least one reporting route is working and monitored as part of the OpenChain evidence register.

Supply a minimal non-sensitive reproduction, version, affected command or generated-template feature, security impact and suggested remediation. Do not include live credentials.

Maintainers will triage privately, evaluate the affected release and its shipped dependencies/templates, record decisions, coordinate remediation and user communications when warranted, and credit reporters as agreed. **No fixed response SLA or guaranteed response time is claimed until an operational response team has adopted and evidenced one.**

See [Zivora Labs OpenChain security-assurance procedure](docs/openchain/SECURITY-ASSURANCE.md). It is a proposed programme, not a statement that ISO/IEC 18974 conformity has been established.
